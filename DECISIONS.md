# ExCamera decisions

## Performance with existing native owners (2026-10-20)

- Decision: reject unrelated mesh submissions after the live root/head pointer checks and before the head drawable's back-pointer and name checks.
- Over: a head-pointer cache held for an entire presentation.
- Because: the controlled head can change inside that presentation. Keeping the current reads and all checks for an actual candidate preserves the existing forwarding and replacement behavior while halving the common scenery path's memory queries.
- Revisit if: native lifecycle evidence provides a reliable head-generation boundary that permits a cheaper gate with equivalent immediate replacement behavior.

- Decision: apply self-pick skip flags during the existing scene walk, using its current full-header range validation for the narrower flags access. Partially readable leaves retain a separate narrow check. Restore only changed flags through the existing finally path.
- Over: caching mesh membership or readability across queries, or keeping skip flags set across unrelated native callbacks.
- Because: this removes duplicate validation without changing node membership, native picking, query scope, ownership, or restoration. The visitor may compact only already-consumed queue entries and makes no native call.
- Revisit if: native equipment/lifetime contracts establish a stable reusable query batch.

- Decision: bound near-plane queries at a six-step legacy bisection endpoint whose view depth already saturates the existing 3 cm near-plane maximum. Resolve closer hits with the original six-step search. Skip the prop query only when the level result already forces the minimum near plane. Reuse held placement's initial level predicate while retaining its final obstruction check.
- Over: cross-sample hit caching, throttled collision checks, altered smoothing or pose sampling, or a newly guessed native closest-hit API.
- Because: effective near-plane results remain identical for the existing monotonic native segment queries; every sample still queries current geometry and retains unknown/fault fallbacks. Quantized endpoints matter at the saturation boundary.
- Revisit if: reviewed native closest-hit/collision-lifetime contracts support a stronger optimization with the same collision and temporal behavior.

These choices do not transfer any camera ownership to ExaniMate. Tests and synthetic query reductions do not establish player-visible camera feel or FPS gains.

## Opt-in hook profiling (2026-10-20)

- Decision: use the same fixed per-thread recorder and callback boundaries on the optimized candidate and the pinned previous release source. Capture control lives in a separate PID-bound, expiring INI request serviced by the existing worker. No new hook, game offset, key or UI control is introduced.
- Because: comparable in-game captures need identical measurement overhead and an unmodified camera algorithm on each side. Callback code performs no file I/O, heap allocation or profiling lock acquisition. Disabled entries read one atomic state and forward immediately.
- Decision: randomly sample roots (default one in 64), propagate selection through nested instrumented scopes, retain exact admitted call counts, separate native/wait spans, and record all owned presentation intervals. Estimate totals by weighting sampled ticks by the inclusion interval. Never add inclusive overlaps or concurrent thread wall times into frame time.
- Decision: combine generation, admission and active root count in one atomic state. Stop closes admission; admitted roots and their children complete; the worker reads only after stable zero roots. Keep bounded thread/nesting limits, explicit drops and exception-safe scope cleanup.
- Because: a separate admission flag and root count allowed a late rejected entrant to make readiness transient. A single modification order removes that race. Return after the SEH finally block, rather than from inside it: MSVC otherwise invokes an expensive local unwind on every successful callback.
- Revisit if: measurements show material observer overhead, thread churn exceeds the fixed capacity, or reviewed native frame/GPU evidence supports a more precise clock boundary. Empty-call microbenchmarks and offline tests do not establish game FPS or camera feel.

## Further performance work with unchanged camera behavior (2026-10-20)

- Decision: share a fresh VirtualQuery protection region only within one mesh callback and only when it contains the complete current head range. Read the current root/head/mesh pointers each time; keep separate-region fallback, candidate back-pointer/name checks and SEH. Both query paths use the existing memory_query span. Full-span containment uses subtraction to reject overflowing ranges.
- Decision: forward foreign pose builds before player focus/input checks, through the same pose_builder.native span. Preserve outer in-flight/health accounting and the entire controlled-player path, including all borrowed-field restoration.
- Decision: stage the four cue outlines and foreground in a bounded stack array, upload once, and keep separate draws in their original order. Keep vertex arithmetic, colors, routing/capability checks, current-context ownership, state snapshots, error handling and finally restoration.
- Decision: reset only TP-prop metadata and publish only active array prefixes under hideLock. Every consumer remains count-bounded and keeps current scene, actor and ancestry validation. No mesh membership is retained across frames.
- Decision: move the normal WGL wrapper returns after finally without changing retirement conditions, native calls, deletion admission, handle identity invalidation, last-error restoration or abnormal unwind behavior.
- Deferred by scope: cue resource lifetime, shader/VAO/VBO re-creation policy, health-counter gating, head-diagnostic sampling, inactive-wear work and throw-queue admission. In particular, switching away still retires cue resources; returning may still require cold preparation.
- Evidence: the production regression compares these owners with frozen 0.2.2-prof1 rev49 bodies using owned memory and Win32/GL/native spies. Offline parity, operation counts and packaging checks do not establish in-game camera feel, driver/GPU timing or FPS gains.

## Warm cue resources with guarded lifetime (2026-10-20)

- Decision: retain complete cue owners across ordinary core WGL switches, compatible DC changes and NULL unbinds, keyed by the exact HGLRC in the existing bounded eight-slot table. Preserve per-context API/capability state and nonshared VAOs. Omit the optional cue when full rather than evict another context's resources. This supersedes only the cue-lifetime deferral above, at the owner's request.
- Over: retiring every switch, sharing one VAO across contexts, or treating a cached DC as ownership evidence.
- Because: repeated native preparation compiled/link shaders and recreated VAO/VBO objects after every return. A DC saved from actual current binding is only an argument for a future native binding attempt; current HGLRC/DC must match before any cleanup. Refresh it after successful native binding and cue admission, including DC changes without a cue draw.
- Decision: serialize observed core WGL operations with cueWglLock, taking cueLock only for resource state/GL work. Native WGL calls run outside cueLock. Bounded same-thread nesting avoids recursive SRW acquisition; reservations protect a deletion's target/caller identities from nested deletion, and GL work rejects reentrant WGL changes with ERROR_BUSY.
- Decision: deleting an unbound warm context temporarily binds it on the deleting caller's thread, verifies actual ownership, retires its resources, and restores the exact caller binding before native deletion. Hold deletion admission closed through restoration and finally cleanup. Native deletion success invalidates the record before another admission can reuse its numeric handle. Shared program/VBO objects are explicitly deleted in their owner; context destruction alone is insufficient when a share group survives.
- Decision: omit cue drawing while native deletion admission is closed, without marking a healthy current owner failed. A reentrant draw during another context's deletion is a temporary omission, not a GL preparation failure.
- Decision: capture separate caller read/draw DCs through the available ARB/EXT WGL family before borrowing. Restore the caller's ICD with the native core binding, then its separate read DC through that context's extension entry and verify both. If a separate binding cannot be captured/restored, fail closed before borrowing or latch failed restoration; never silently replace its read surface with the draw surface.
- Because: making a context current natively enforces single-thread ownership. A failed bind may unbind the caller, so restoration runs on failures and exceptions too. Unknown/stale DC, foreign-current, incorrect binding or incomplete GL cleanup fails closed without deleting the native context. Failed binding restoration latches cue_binding_failed, stops admission and keeps teardown/re-arm blocked; it never claims successful cleanup.
- Decision: stop closes cue allocation before draining; callbacks retire the current owner before and after native switches and on cue-free native frames. Drain warm owners before disabling lifecycle hooks, including partial-arm rollback. Begin/re-arm opens admission only after an empty, quiescent, fault-free table. No worker thread binds a context or performs GL deletion. A dormant owner that cannot return or delete leaves the existing bounded stop in retained/pending state.
- Revisit if: actual captures show pressure beyond eight admitted native contexts, an additional context-binding/deletion API needs interception, or a reviewed owner-thread retirement protocol can safely clear a dormant owner without its callback. No new game-memory operation, camera algorithm or profiling boundary is introduced.

## Health, diagnostics and inactive wear (2026-10-20)

- Decision: stop health-counter increments only after the worker has made its existing five-second game-clock verdict. Reopen recording before native hook enable on each arm; retain cumulative totals and the fresh re-arm health state. Menus, pause, interrupted windows, compatible-build failure/stop policy and partial-arm rollback remain unchanged. An already-admitted late increment cannot change a fixed verdict; the next window snapshots the totals again.
- Decision: coalesce head-diagnostic demand from the once-per-second running-status writer. Consume it on the next native camera sample that reaches the original diagnostic block after current ownership, scene, head and pose checks. Startup/re-arm begins with demand pending. Keep the same range query, geometry arithmetic, finite-value publication and last-successful values on failure. Retain no game pointer or readability result between samples; the worker never reads head geometry. This supersedes the diagnostics deferral above.
- Over: throttling camera/pose/collision samples or moving game-memory work to the worker. Status diagnostics can now be about one status interval old; they remain last-successful diagnostics, not a camera input or guaranteed current-head identity.
- Decision: clear the existing wear caches, counters and pending publications before returning for inactive or mismatched camera ownership. Defer head validation until head wear can act, and defer the body-root range query until the existing look-down and ownership gates pass. Preserve all active-path validation, retest cadence, skin/foreign exclusions, native ray behavior, fault boundaries and application-time ownership checks. This supersedes the health/wear deferrals above; throw-queue admission remains deferred.
- Evidence: frozen prof3 production bodies and owned-memory fixtures check exact active behavior and operation counts. Existing temporal camera integration alternates diagnostic demand without changing sample/pose/filter results. These checks establish offline parity, not in-game FPS or feel.
- Revisit if: a new consumer needs frame-current diagnostics or health totals after the verdict, or native lifetime evidence changes wear ownership. Such a consumer must explicitly revise the demand/counter contract.

## Empty throw queue admission (2026-10-20)

- Decision: publish a nonempty hint under heldThrowLock after every queue mutation, including cancellation, replacement/expiry, both native-release phases and final history delivery. Every nonempty phase counts. The ordinary-body integrator may skip only its table lock/scan after an acquire load observes empty; a true observation still locks and runs the original current-ticket checks. This supersedes the throw-queue deferral above.
- Over: caching body membership, gating on settling tickets alone, changing throw timing, or skipping the destructor when the table is empty.
- Because: most integrated bodies have no optional throw ticket. An empty observation can linearize before an overlapping insertion, just as the previous locked empty scan could. All native calls stay outside the lock. Integration depth and native forwarding remain unconditional; a fault still locks and cancels the body because a ticket may have been inserted during that native call. Destruction still unconditionally increments flingLifetimeEpoch under the lock before body cancellation, fencing captures not yet published even if no ticket exists.
- Decision: derive the hint from the bounded table at mutation boundaries rather than maintaining an independent occupied-slot count. The hint conveys no pointer, lifetime or permission; the locked table remains authoritative. Every successful history write still uses the original owner/worker/body checks and atomic staged twelve-float helper.
- Revisit if: another table writer or phase is introduced, native scheduling/publication contracts change, or measurements show the rare mutation scans matter. New writers must publish before unlocking; absence of a ticket never waives lifetime invalidation or exception cancellation.

## Cursor Look and headwear handoff merge (2026-10-20)

- Decision: restore held exploration Cursor Look through the game's existing Controls binding (native slot 8). Add no key, INI binding, native table mutation or duplicate settings row. Camera/pose/collision algorithms remain unchanged.
- Because: the supplied d39eff0 handoff is an older source delta, while prof5 owns the accumulated performance and lifetime work. Merge its deltas rather than replacing full files. Preserve native profiling around input, inactive wear gates and active query counts. The archived reference image independently confirms the native Cursor Look descriptor/conversion and existing slot contract.

## First-person headwear render ownership (2026-10-20)

- Decision: use the existing native 4E610 main colour traversal and 6B8B0/6B7F0 draw boundaries. Admit only the reviewed source with complete loaded-body equality, current controlled actor/head, main viewport/camera, sector, bidirectional attachment and material membership. Rebuild bounded rejection hints inside each traversal; retain no geometry/readability proof between draws. A newly attached material can enter hints on the next traversal; bound uncertainty disables rejection. Every match repeats full live validation.
- Because: the old physical-head-descendant scan misses equipment appended to the actor-root _SKIN aggregate. Native D9350 and 69520 preserve face tags through material sorting, and 5E340 emits one triangle list in the same face order. Classify only faces whose positive normalized weights all belong to the verified head branch; use tags to distinguish base head from equipment and group obstruction. Mixed neck/body faces remain native, even in a shared material. Whole-skin/material suppression would remove unrelated geometry.
- Decision: copy bind positions, normals and tangents, transform them through the head inverse bind (or the verified separate attachment's local mount chain), then draw visible headwear at the exact native temporal view's eye mount. Keep original projection/crop/depth offsets through the native model/MVP pair. Disable culling only during headwear runs and restore all borrowed attributes, bindings and uniforms in finally. No physics, camera, native geometry, callback, mask or transform write.
- Because: native headwear animation was retained while the camera used its displayed physical-head sample and stabilized look; an explicit first-person render attachment is needed to prevent visible relative motion. Drawing inside a single-sided helmet also requires a local two-sided treatment. Other actors, shadows, third person and overhead must retain native animation/culling. This supersedes the prof6 deferral only for this reviewed render path.
- Decision: retain the existing separate-attachment ray/mask checks and additionally test copied stable triangles with the same five-ray cone, from either winding. Hide obstructing pieces in both modes; on upload/resource failure omit visible headwear while retaining native body runs. Uncertain native ownership/layout forwards before edits. Base head geometry stays hidden independently of the setting.
- Decision: lazily add one separate headwear VBO to the existing exact-HGLRC warm owner rather than introduce another context cache or reuse the arc upload. It is included in live ownership and retirement, closed admission, deletion borrowing and stop drain. Rendering borrows cueLock/GL-depth protection; only the reviewed GL-only native binders execute under it, with context-switch/drawing reentry rejected. No gameplay, entity or camera callback executes under that lock. One lazy bounded CPU staging allocation is protected by a nonblocking draw lock, rather than duplicated into every thread through static TLS.
- Evidence: source-bound native contracts, production Windows fixtures and owned hidden-window WGL pixel tests. These establish offline render behavior, not the actual player's equipment coverage, gameplay camera feel or FPS. Revisit mixed-bone apparel only with explicit source coverage/lifetime evidence; it must not be guessed into the head branch.

Generic clone516B0 initially shares the source group table; equipment constructorE6FF0 calls635E0 to allocate groups with the instance back-pointer. ## Fault-safe hook locks (2026-10-21)

- Decision: nav, swap and cursor-position hooks acquire cameraLock and run their former body in a separate function under __try/__finally; behavior() releases aimLock in __finally when updateAim faults while holding it. Faults still propagate.
- Over: /EHa, swallowing faults, or a recursive lock.
- Because: under /EHsc an SEH unwind past CameraGuard need not run its destructor, and updateAim had no release on unwind. A fault reading a dying character, caught by the game, left the lock held and the next acquire blocked the game thread forever. Observed: the status writer stopped at the moment of death. After the change one in-game death did not freeze. Static reading plus one live run; the leaked-lock mechanism itself was not observed directly.
- Revisit if: another blocking lock is held across unguarded game-memory reads on a game-thread hook. Inner aimLock/reticleLock spans inside these regions copy mod state only.

## Per-call readability sharing (2026-10-21)

- Decision: within one call with no intervening native call, reuse the last fresh VirtualQuery region (scene walks, self-pick restore, near-plane ancestors, form scans) and skip a repeated query of the same node or range. Head-wear branch verdicts are memoised by index, since parents precede children in the walk. windowProc tests the message type before gameplay predicates.
- Because: same results with fewer system calls on per-frame and per-message paths. Nothing is retained across calls; this extends the existing per-mesh-callback sharing decision.

## Decal depth offset floor (2026-10-21)

- Decision: keep the near-ratio scaling of authored P10 offsets, but never let a non-terrain offset fall below min(|authored|, 16 depth steps = 16·2^-23 NDC).
- Because: 1DD50 builds an infinite-far frustum, so an authored P10 addition is a constant NDC shift at any near. Blood (+1e-5, overlay 100820) and scene decals (+2e-5, 4F750) scaled by 3 cm / 100 cm land near one 24-bit step and z-fight. Sixteen steps is about 0.3 cm of poke-through at 1 m with a 3 cm near. Offline: 1e-5 at stock 100 / near 3 becomes 1.91e-6; unbiased P10 untouched. Not yet seen in game.
- Revisit if: decals show through thin geometry in front of them, or the depth buffer is not 24-bit.

## View effects and VR merged (2026-10-21)

- Decision: merge the post-FX view effects (sampled-views detour 0xA0CE0, world-pass return 0x4BF39) and the OpenXR emulation integration into this tree, porting by intent onto today's fault-safe and dev-build changes. Generated tables are regenerated once from the reviewed EXE; both groups are optional and admitted only on whole-function byte-exact contracts (file and loaded image).
- Because: the installed Hellmode EXE differs from the reviewed one by 17 bytes outside every hooked function; source-hash gating kept the effects off there. Offline admission passes on both EXEs; the Hellmode title run admits view effects with 333 checks and no faults. VR is compiled only with --openxr-sdk.
- Open: deleting a non-current context whose DC is gone with live view resources is still refused (reviewed WGL deletion contract). Under supersampling the effects run once on the averaged image (4B6D0), reading the view's own matrices.
