## Cause and owning implementation

The old headwear owner scans descendants of the physical 10Head node, while native apparel can append equipment faces to a sibling _SKIN aggregate. The supplied runtime snapshot requested hide, accepted zero attachments and still showed helmet/hair. The production fixture reproduces that topology and scan result. Visible gear also retained native animation and single-sided culling, with no first-person render attachment. This establishes source defects and a reproduced aggregate path; it does not identify every triangle in the player's actual equipment.

The replacement extends the existing standalone renderer at the reviewed 4E610 main colour traversal and 6B8B0 / 6B7F0 indexed draws. It adds no competing camera/input/physics owner. Existing attachment visibility rays, masks and application-time checks are unchanged. Native queue/head filtering, shadow submission and other camera views retain their original behavior.

## Render, safety and lifetime

Copied stable triangles receive a finite two-sided five-ray cone test with the existing cone/length and eye setback. A blocker hides its verified headwear group in both modes, in addition to unchanged native attachment ray checks. Base head faces stay hidden. Unknown or mixed ownership is not widened into equipment. Face and vertex limits32768, bones256 and obstruction groups64 bound work and allocation. A group-capacity overflow hides gear conservatively.

One lazy bounded CPU staging allocation is protected by wearScratchLock (TryAcquire); concurrent/reentrant draws forward without waiting. It contains copied data only and remains warm across context/view changes. The rejection-only material hints are scoped to one native colour traversal, sorted and bounded512. Full provenance/ranges are checked again on every match. A newly attached material may enter on the next traversal; overflow/uncertainty disables rejection. No stale hint authorizes a native write. Scenery rejection has a 100000-draw zero-query regression.

GPU order: wearScratchLock -> cueLock. API resolution, native GL-only binding, vertex upload and drawing happen with cueGlDepth active. Drawing reentry from guarded GL cleanup forwards before attempting either lock. No CPU geometry source is retained after the draw. The optional headwear VBO is a separate field in the existing exact-HGLRC CueResources owner. live()/retire() include it, so ordinary switches keep it warm, shared-group deletion explicitly retires it in its owner and stop/re-arm remains blocked until owners drain. Context caches, deletion borrowing, read/draw DC restoration and worker no-GL policy are unchanged.

GL state capture is complete before custom changes: current VAO and array/EBO bindings, relevant floating vertex attributes and source buffers/pointers/stride/type/normalization, cull enable and both native matrices. Enabled/integer/type compatibility is checked; the operation does not change enable/divisor/program/texture/depth/blend/framebuffer state. Only gear runs use the stable stream and disabled culling. Native body runs use their original attributes/matrices/culling. Finally restores VAO, every borrowed attribute, matrices and bindings on success or exception. Upload failure omits gear while keeping body runs. A draw exception restores state and propagates; it is never retried as a duplicate native draw.

## Review outcome and proof limits

Concrete issues corrected during review: static TLS would replicate about1.8MiB of scratch into every game thread (replaced with one lazy bounded allocation); guarded GL-cleanup reentry could recurse cueLock (early depth rejection added); helper/API resolution before the GL-depth guard permitted an observed core-WGL switch before owner admission (moved inside guarded work); original EBO binding semantics must be captured after the native bind, not restored to a pre-bind value. Attribute tests compare values rather than struct padding.

Production regressions cover old aggregate miss, shared body/neck material preservation, helmet/hair/bevor tags, separate mount and foreign owner rejection, hide/show, two-sided blocker winding/grouping, four temporal samples, bounds, upload failure, SEH and reentry restoration, no duplicate draw, hint rejection and native-memory byte equality. The reference-image fixture mutates every complete loaded-body witness and verifies capability withholding / retained-hook re-arm refusal / unrelated-group preservation. Modeled and native WGL lifetime checks include the new VBO, warm switches and owner deletion/drain.

Owned hidden-window NVIDIA/OpenGL pixel evidence reproduces a missing backface (0pixels), draws91pixels with the fix, retains the same image after arbitrary native animated-VBO perturbation, removes it in Hide, verifies GL restoration, and reuses/retires the warm stream. These are real GPU fixture results, not Exanima gameplay or a measurement of FPS/camera feel. The actual player's equipped helmet/hair/bevor, mixed-bone coverage, lighting and scene/equip transitions still require in-game acceptance. Mixed body/neck geometry deliberately retains native rendering. No install, activation, publication, save access or live-game acceptance is claimed.
